# The end-to-end roadmap

Load only the branch needed for the current step. Start with local drafts and inspection. Offer hands-on browser help when the user needs it. Save all business artifacts in their private run.

## Business choices

Ask for budget amount/type, currency, start/end dates, and the maximum total spend the owner authorizes for this test. A daily budget isn't a lifetime cap. State any platform budget flexibility and actual account-level controls using current official documentation. Do not promise an unsupported hard cap. If the user has no starting budget, propose a range only after research and explain the uncertainty; get an approved amount before creation.

Ask who the intended customer is, then check what targeting controls actually exist. A “homeowner” description isn't necessarily a targeting switch. A lookalike needs an eligible source; don't manufacture one. Check current special-category requirements for the actual offer. Don't suggest discriminatory targeting. If the user's business is outside the local-service examples, adapt the goal, destination, qualification and metrics rather than forcing appointment-lead ads onto every product.

## Build and review

Use the simplest campaign structure that fits the test budget and goal. Record an ad-level plan while media is pending; don't claim a complete ad exists if Meta requires missing assets. Before writes, show the exact objects/settings to create and confirm the intended account. Before retrying a timed-out write, search/read for the object to avoid duplicates. Correct mismatches inside the approved scope; don't change unrelated campaigns.

Use templates for a concise plan and review packet. Keep a source record of user approvals and save the current configuration digest (see `docs/STATE.md`). The helper can check local readiness and stale approvals. It does not verify Meta. The agent still inspects actual saved objects and previews.

## Launch is optional

“Set up my ads” authorizes working through preparation, not an unspecified charge. Show the account, object IDs, exact budget/type/currency, dates/timezone, max authorized total, destination, creatives and remaining limitations before asking for launch approval. If these change, obtain approval for the revised values. Do not add a second confirmation when the user already approved these exact values and scope.

If the user wants to stop before launch, leave everything paused and save the next action. After approved activation, report actual status; acceptance for review is not proof of delivery or performance. Monitor against the owner's approved spend and stop/escalate within their instructions; do not autonomously scale or claim profit before outcomes exist.
